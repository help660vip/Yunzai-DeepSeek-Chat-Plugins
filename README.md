# Yunzai DeepSeek Chat

给 Yunzai 用的 QQ 聊天插件，支持私聊和群聊。除了聊天，还能记住当前会话、归档旧消息、统计用量、拉黑和导出记录，也能查看群成员之间的互动。

平时按群友的语气接话，闲聊一般一两句，用空格或换行停顿，少用标点。认真问题按需要展开，代码、公式、网址和规范写作保留必要符号。不知道就直说，不编答案，也不因为问题长就拒绝回答。

## 安装

需要 Node.js 18 或更新版本，以及已经能正常运行的 Yunzai。插件入口使用 Yunzai 的 `lib/plugins/plugin.js`。下面以 Linux 部署为例，把路径换成自己的：

```bash
cd /path/to/Yunzai
git clone https://github.com/help660vip/Yunzai-DeepSeek-Chat-Plugins.git \
  plugins/Yunzai-DeepSeek-Chat-Plugins
```

使用 Node.js 自带的 `fetch`，没有额外的 npm 依赖。

把 API 配置放进 Yunzai 的启动环境，再重启进程：

```bash
export DEEPSEEK_API_KEY='你的 API Key'
export API_BASE_URL='https://api.deepseek.com'
export API_MODEL_NAME='填写服务商支持的模型名'
```

接口需要兼容 Chat Completions。换服务商时，Key、地址和模型名要一起核对；使用 `SILICONFLOW_API_KEY` 也需要配置对应地址和模型。

插件只读进程环境变量，不会自动加载 `.env`。用 PM2、systemd 或 Docker 启动时，要在对应的进程配置里设置。PM2 可以用下面的命令更新环境，进程名按 `pm2 list` 中的实际名称填写：

```bash
pm2 restart yunzai --update-env
```

## 配置

API 和提示词在 [`config/config.js`](config/config.js)。这些参数可以通过环境变量修改：

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 无 | API Key，必须配置一个有效的 Key |
| `SILICONFLOW_API_KEY` | 无 | 没设置上面的 Key 时使用 |
| `API_BASE_URL` | `https://api.deepseek.com` | API 根地址；有些服务商需要带 `/v1` |
| `API_MODEL_NAME` | `deepseek-v4-flash` | 源码预设值，部署时按服务商支持的模型填写 |
| `API_MAX_TOKENS` | `2048` | 普通用户单次输出上限，最多可设 `16384` |
| `API_MASTER_MAX_TOKENS` | 不设置 | 主人单次输出上限；不设置就由服务商决定 |
| `API_MASTER_TIMEOUT_MS` | `300000` | 主人请求超时，单位毫秒 |
| `CHAT_MASTER_HISTORY_TOKENS` | `64000` | 主人的历史窗口预算，不包含当前问题和引用 |
| `CHAT_MAX_PROMPT_TOKENS` | `12000` | 普通用户输入预算，最多可设 `64000` |
| `CHAT_DAILY_USER_TOKENS` | `60000` | 每人每天的 token 预算 |
| `CHAT_DAILY_GROUP_TOKENS` | `300000` | 每群每天的 token 预算 |
| `CHAT_DAILY_GLOBAL_TOKENS` | `1000000` | 整个插件每天的 token 预算 |

数值环境变量只接受正整数，无效值会使用默认值。修改环境变量或源码配置后都要重启 Yunzai。

其他常用参数在同一文件的 `LIMITS` 中：

| 参数 | 默认值 | 用途 |
| --- | ---: | --- |
| `cooldownMs` | `3000` | 普通用户两次请求的间隔，单位毫秒 |
| `rateLimitPerMinute` | `10` | 普通用户每 60 秒最多请求次数 |
| `groupRateLimitPerMinute` | `30` | 每群每 60 秒最多请求次数 |
| `globalRateLimitPerMinute` | `60` | 插件每 60 秒最多请求次数 |
| `maxConcurrentRequests` | `4` | 普通请求的同时运行数量 |
| `maxMessageChars` | `4000` | 普通用户单条输入字符上限 |
| `maxQuotedChars` | `2000` | 普通用户引用消息的字符上限 |
| `maxContext` | `500` | 单个会话最多保存的消息条数 |
| `maxPublicMemory` | `100` | 每群最多保存的公共消息条数 |
| `archiveThreshold` | `400` | 自动归档的消息条数阈值 |
| `maxArchivesPerRun` | `3` | 一次自动归档最多尝试的会话数 |
| `randomBubbleChance` | `0` | 普通群消息触发回复的概率，范围 `0` 到 `1` |

默认关闭随机冒泡。私聊、群里 @ 机器人、回复机器人消息仍会触发聊天。想让机器人偶尔插话，可以把 `randomBubbleChance` 改成 `0.01`，即每条普通群消息有 1% 的概率触发。

## 主人长答和普通用户额度

主人身份以 Yunzai 提供的 `isMaster === true` 为准，在消息里自称主人没有用。请先在 Yunzai 配好主人账号。

主人聊天不受本地冷却、请求次数、普通并发名额、每日额度和单条输入长度限制。普通用户用完额度或占满名额时，主人仍能提问；当前问题和引用会完整发送，历史使用单独的较大窗口。

主人聊天默认不发送 `max_tokens`。如果服务商的默认输出太短，可以用 `API_MASTER_MAX_TOKENS` 设置该模型支持的输出上限。默认等待最多 5 分钟，长答不会按字符数截断。模型和服务商自己的上下文、输出与速率限制仍然生效。

同一用户跨群的重复请求保护仍保留，避免一条请求没结束又连续发起多条。黑名单也照常生效。主人用量记入统计，但不扣普通用户额度；主人手动归档同样获得额度豁免，后台自动归档按普通额度处理。归档和关系分析各自使用较短的输出上限，不影响正常聊天的长答。

普通用户的聊天、关系分析和自动归档共用限流和每日预算。请求按滚动 60 秒计数，失败也保留冷却；限额提示每人最多 30 秒发一次。普通请求默认 60 秒超时，暂时性错误最多尝试两次，401 等永久错误和超时不会自动重发。

每日预算按北京时间零点重置，账本写入 `meta.json`，重启或清空对话不会重置额度。每次网络尝试都会先预占输入估算和输出上限，再调用 API；服务商返回有效用量时按实际消耗结算。失败、超时或没有用量数据时保留预占，所以“今日预算占用”可能比已确认用量高。

输入按 UTF-8 字节数保守估算，预算不是服务商账单。当前限流和存储按单个插件进程设计，多进程运行需要另外接共享存储。

## 记忆怎么处理

每次请求都会带系统提示词，并在当前问题前补一段简短提醒。长历史按最近的完整对话轮次保留，系统规则和当前问题不会被裁掉。普通用户输入超出预算时会收到提示，不会偷偷截断问题。

昵称、引用、群消息、摘要和个人信息只作为参考数据，不会被放进系统指令。这样能减少旧回复带偏语气的情况，但模型偶尔仍可能没按要求说话。

个人记忆按群和私聊分开，只读取当前会话的摘要与信息。旧版本按用户全局保存的信息只在私聊读取，不会自动搬到群里。

自动归档会合并上一份摘要，逐段总结最早的消息，只删除实际总结过的部分。摘要无效时保留原记录。摘要会丢失细节，消息达到存储条数上限时也会淘汰最旧记录，不适合当完整聊天备份。

群里的 @ 和引用互动会直接记录，不需要先触发机器人。关系统计只能反映插件收到的消息。

## 指令

普通用户：

| 指令 | 用途 |
| --- | --- |
| `#清空我的上下文` | 清空当前会话的个人上下文、归档和提取的信息 |
| `#对话统计` | 查看自己的对话统计 |
| `#查询关系 @A @B` | 分析两名群成员的互动 |
| `#群关系图` | 查看群内互动概览 |
| `#我的社交统计` | 查看自己的群内互动统计 |

主人：

| 指令 | 用途 |
| --- | --- |
| `#删除全部上下文` | 清空全部会话记忆和群公共记忆 |
| `#查看上下文条数` | 查看存储的消息条数 |
| `#你用了多少 token` | 查看用量和今日预算占用 |
| `#归档上下文` | 手动归档较长的会话 |
| `#对话拉黑群 群号` | 拉黑群 |
| `#对话拉黑人 QQ号` | 拉黑用户 |
| `#对话解除拉黑群 群号` | 解除群黑名单 |
| `#对话解除拉黑人 QQ号` | 解除用户黑名单 |
| `#对话黑名单` | 查看黑名单 |
| `#对话调试模式 开启` / `#对话调试模式 关闭` | 切换调试日志 |
| `#导出对话记录 @用户` | 导出用户对话记录 |
| `#导出群聊天记录` | 导出当前群的公共记忆 |

导出生成的是服务器上的文本文件，指令会返回文件路径。群聊、引用和主人权限需要 Yunzai 适配器提供对应字段。

`#清空我的上下文` 不影响自己在其他群或私聊的记忆，也不删除整个群的公共记忆。请求进行中清空，旧结果会被丢弃。`#删除全部上下文` 用于彻底重置会话记忆，两条指令都不会清零当天额度、用量统计或社交统计。

## 数据和排障

数据在 Yunzai **进程工作目录**下的 `data/aitalk/`，不是插件目录：

| 文件或目录 | 内容 |
| --- | --- |
| `context.json` | 个人上下文和群公共记忆 |
| `archive.json` | 归档摘要 |
| `important.json` | 当前会话提取的个人信息 |
| `stats.json` | token 用量 |
| `blacklist.json` | 黑名单 |
| `relationships.json` | 群成员互动 |
| `meta.json` | 当天预算和备份元数据 |
| `backup/` | 自动备份，默认保留 7 天 |
| `exports/` | 导出的文本记录 |

对话数据会保存在本机，参与回答的内容会发送给配置的 API 服务商。备份和导出文件不会被聊天流程自动读取。数据目录和 API Key 都不要提交到仓库。

常见问题可以先查这几项：

- **没读到 Key**：确认变量在 Yunzai 进程里生效。终端执行过 `export`，不代表 PM2、systemd 或容器已经加载。
- **冒泡设为 0 还回复**：先重启，再看消息是否 @ 了机器人或回复了机器人；这些属于正常触发。
- **语气还是受旧消息影响**：更新后重启，必要时用 `#清空我的上下文` 清掉当前会话记忆。
- **API 报错**：核对根地址是否需要 `/v1`，模型名是否可用，再看日志中的 HTTP 状态码。
- **保存失败**：确认工作目录和 `data/aitalk/` 的读写权限；容器部署要挂载持久卷。

## 修改和测试

消息处理在 `services/chat.js`，API 请求在 `services/api.js`，限流在 `services/request-guard.js`。存储和额度账本在 `services/storage.js`，上下文组装在 `utils/context.js`，互动统计在 `services/social.js`。

测试使用 Node.js 内置测试运行器，不调用真实模型：

```bash
npm test
```

问题可以发到 [Issues](https://github.com/help660vip/Yunzai-DeepSeek-Chat-Plugins/issues)，附上复现步骤、Node.js 版本和去掉 Key、QQ 号及聊天内容的相关日志。
